4Basic interfaces

An IDM has five parts; the left bar opens each one, and the process map is always in the middle.

Video 4 of 10 · 1:18 · open the MP4 · subtitles (.srt)
The video could not be loaded here. Open index.html from the tutorial folder in a web browser (not in a preview window), or open the MP4 directly.
  1. a Header — identifiers, title, version, status, authors and revisions.
  2. b Use case — summary, aim and scope, uses, region, actor roles, project phases.
  3. c Process map (PM) — a BPMN editor with pools, lanes, tasks, events, gateways and data objects.
  4. d Exchange requirement (ER) — the ER hierarchy; select an ER to edit its information units.
  5. e Rule — business rules and their constraints.
  6. Validate checks the IDM against ISO 29481-3; Save & Export saves it.

5 · Learning through an example

Build the IDM Defect Management Using BCF from a blank project, part by part.

The example: defect management

On a building site, a defect is identified, logged, triaged, assigned, rectified, verified and closed, and every day at 17:00 the open defects are reported. Each step hands over a form. The example is fictitious: the Riverside Medical Office Building, where fire door D-3F-12 does not close by itself (defect DEF-0001).

1 IdentificationDefect inspection form
2 LoggingDefect log entry (BCF topic)
3 TriageTriage record
4 AssignmentDefect assignment notice
5 ResolutionRectification report
6 VerificationVerification record
7 ClosureDefect closure record
Every day at 17:00 · Reporting and analysisDefect status report for the owner's representative

5eMapping information units to external elements

i. What is BCF · ii. Mapping defect information to BCF elements.

Video 9 of 10 · 1:57 · open the MP4 · subtitles (.srt)
The video could not be loaded here. Open index.html from the tutorial folder in a web browser (not in a preview window), or open the MP4 directly.
  1. A mapping says where an IU is stored in a data format that tools already support.
  2. Select Storey › + Add Mapping › IFC 4x3 ADD2, search IfcBuildingStorey, and edit the path to IfcBuildingStorey.Name.
  3. BCF exchanges issues as topics with viewpoints: one topic per defect.
  4. Select Title in the defect log entry › + Add Mapping › + Add schema… › preset BCF 3.0; search Title and apply Markup/Topic/Title.
  5. Severity has no BCF field: it travels as a label. The catch-up file has all 64 mappings.

5fSpecifying rules

Business rule → constraint → expression; then validate and export.

Video 10 of 10 · 1:49 · open the MP4 · subtitles (.srt)
The video could not be loaded here. Open index.html from the tutorial folder in a web browser (not in a preview window), or open the MP4 directly.
  1. Use Case › Business rules… › + Add: Safety-critical defects — “A defect that is flagged as safety-critical shall have the priority P1 - Critical.”
  2. Constraints › + Add: ER Triage record; Select IUs Safety-critical and Priority.
  3. Description: IU-TRI-05 = true IMPLIES IU-TRI-03 = 'P1 - Critical'. + Add expression adds SHACL, SPARQL, Python …
  4. Open the finished IDM, Validate (0 errors, 0 warnings), and Save & Export idmXML 2.0 and HTML.

Constraint
